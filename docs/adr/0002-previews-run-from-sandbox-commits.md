# Run previews from sandbox commits

A preview stack copies the sandbox volume once at start and never looks at it again, so an agent edit reaches the running application only through a full rebuild. The sandbox is already a git repository, so agent work becomes a task branch and a preview becomes an export of one commit. Git supplies the temporary storage, the diff, the accept path, and the reject path that a volume snapshot layer would otherwise have to reinvent, and a commit identifier replaces the protected-file hash map as the thing an approval points at. Two preview kinds follow from this: a live preview bind-mounts the sandbox volume so the development server reloads as the agent writes, and a task preview exports an immutable commit so a human reviews exactly what merges.
