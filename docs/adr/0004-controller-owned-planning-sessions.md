# Plan features in controller-owned planning sessions

A feature reaches a coding agent as one paragraph of prose, so scope, constraints, and trade-offs are settled inside a container whose reasoning the controller never sees and whose conclusions no human approved. Planning therefore becomes its own controller-owned artefact: a session that holds a clarification conversation, a planner transcript, a reviewer ledger, and one final Plan Spec, all in the controller database rather than in agent-writable files. Models run headless, one short-lived container per turn, with the project volume mounted read-only, so a planning model can read the code it plans against but holds no authority to change it. The controller replays the whole transcript into each turn instead of resuming a CLI session, because conversation state that lives in a credential volume is neither trusted metadata nor recoverable after that volume is rebuilt. Agreement is an explicit human act: the model summarises its understanding and the human confirms, corrects, or orders it to proceed, so no plan is ever built on a shared understanding that only the model believed it had. The session ends at a Plan Spec ready for human review, and produces no tech spec, no task, and no branch, because a plan a human has not read is not a mandate to change a repository.
